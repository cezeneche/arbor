Under the definitive regime it is an annual declaration, and indirect emissions count only for cement and fertilisers. Check the wording against the Commission's guidance and fix every screen that repeats it.
  - Done. It turned out to be a calculation bug too: the engine and the EU declaration file added indirect emissions for every good. The owner approved the change and the four golden cases it moved (steel lines only; each now equals its direct emissions).
- [x] **A2. Keep HMRC reference data current.**
  - Exchange rates: Nucleos's table (`nucleos/api/app/services/cpr_reference.py`) holds only 2026 rates for EUR and USD (and January 2026 only for CNY, TRY and INR), and none for CHF or SEK. The relief form therefore says "not held" for every 2027 claim.
  - UK CBAM rates: the same will apply to the quarterly rates once HMRC publishes them.
  - Build a monthly import from HMRC's published exchange rates into the versioned table (insert-never-update, new table version), with a test and an alert when a month is missing.
  - Done. The table's rows were wrong: labelled "HMRC monthly rates" but matching none of HMRC's files (EUR Apr 2026 0.8365 vs HMRC 0.8643; TRY off by 31%). They are replaced with HMRC's published files for January–October 2026: 141 currencies, including CHF, SEK and NOK. The data lives in `hmrc_exchange_rates_data.py`, generated by `nucleos/scripts/update_hmrc_rates.py`; the version is now `hmrc-monthly-2026-10`.
  - `.github/workflows/hmrc-rates.yml` runs every Friday: it fetches new months, opens a PR (or an issue with a link to open one, if Actions may not create PRs), and fails when the current month isn't on main.
  - 2027 rates arrive as HMRC publishes each month, the month before it starts.
  - Still open: UK CBAM quarterly rates once HMRC publishes them (not yet available).
